# Блог AbeloHost

## Что уже сделано

В текущем состоянии проект отвечает требованиям задания: есть главная страница, страницы категорий и статей, сортировка и постраничный вывод, похожие статьи, MySQL, Smarty, начальные данные и Docker-окружение.

Публичные страницы обрабатываются через `public/index.php`. Nginx не открывает исходный код приложения и запрещает прямой доступ к другим PHP-файлам.

Позже можно добавить кэширование данных статей в Redis. Так сайт будет реже читать неизменившиеся данные из MySQL, а счётчик просмотров продолжит работать отдельно. Также естественным следующим шагом была бы админка для создания и обновления статей. В исходном задании админка не требовалась, поэтому её здесь нет.

## Запуск с нуля

Все команды ниже запускаются в обычном терминале на компьютере, из корневой папки проекта. Входить в Docker-контейнер вручную не нужно.

1. Установите Docker с Docker Compose и `make`.
2. Откройте терминал в папке проекта.
3. Выполните:

   ```sh
   make setup
   ```

Эта команда соберёт и запустит контейнеры, установит PHP-зависимости, создаст таблицы и добавит начальные категории и статьи. После завершения откройте [http://localhost:8088](http://localhost:8088).

## Команды проекта

Команды можно запускать из корневой папки проекта.

| Команда | Простыми словами |
| --- | --- |
| `make setup` | Первый запуск: собрать и запустить проект, установить PHP-зависимости, подготовить базу и заполнить её начальными данными. |
| `make up` | Собрать Docker-образы и запустить службы проекта. |
| `make install` | Установить PHP-зависимости в контейнере приложения. |
| `make migrate` | Создать в MySQL недостающие таблицы и применить новые изменения базы. |
| `make seed` | Добавить начальные категории и статьи. Команду можно запускать повторно. |
| `make test` | Запустить полный набор модульных и интеграционных тестов в отдельных тестовых контейнерах. |
| `make test-unit` | Запустить только модульные тесты. Для этой команды приложение должно быть запущено командой `make up` или `make setup`. |
| `make cs-check` | Проверить оформление PHP-кода. Для команды нужны PHP 8.4+ и Composer на компьютере. |
| `make cs-fix-git` | Исправить оформление PHP-файлов, которые уже добавлены в Git. Файлы зависимостей и кэша пропускаются. Нужны PHP 8.4+ и Composer на компьютере. |
| `make cs-fix-all` | Исправить оформление всех PHP-файлов проекта, кроме зависимостей и кэша. Нужны PHP 8.4+ и Composer на компьютере. |
| `make cs-fix` | Короткое имя для `make cs-fix-all`. |
| `make flush-views` | Немедленно перенести накопленные в Redis просмотры в MySQL, не дожидаясь планировщика. Проект должен быть запущен. |
| `make styles` | Установить зависимости оформления и собрать CSS из SCSS. Для команды нужны Node.js и npm на компьютере. |
| `make logs` | Показать последние записи журналов сайта, PHP, MySQL, Redis и службы подсчёта просмотров. |
| `make down` | Остановить службы проекта и тестовые службы. Сохранённые данные MySQL и Redis остаются в Docker-томах. |

## Тесты и оформление

Чтобы проверить проект после запуска, выполните:

```sh
make test
```

Команда поднимет отдельную тестовую базу и Redis, выполнит тесты и остановит временный контейнер тестов. Для одного только быстрого запуска модульных тестов используйте `make test-unit`.

Чтобы собрать стили после изменения файлов в `resources/scss`, выполните `make styles`.

Чтобы проверить или автоматически поправить оформление PHP-файлов, используйте `make cs-check`, `make cs-fix-git` или `make cs-fix-all`. Эти команды запускают PHP CS Fixer на компьютере, а не в контейнере.

Сейчас конфигурация PHP CS Fixer ссылается на два пользовательских исправителя, исходных файлов которых в проекте нет. Поэтому эти три команды могут завершиться ошибкой, пока исправители не будут добавлены или их подключение не будет убрано из конфигурации.

## Просмотры статей

Просмотры сначала накапливаются в Redis. Контейнер `views-worker` запускает задачу по расписанию каждые 30 минут и переносит накопленные значения в MySQL. При необходимости перенос можно запустить вручную командой `make flush-views`.
